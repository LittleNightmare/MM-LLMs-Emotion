# 作业要求与参考论文对照

核查范围：课程《大作业.pptx》《大模型后训练.pdf》、当前仓库 README 和基线记录、Zotero 中课程指定的三篇论文全文，并补查作者仓库和数据集官方说明。本文中的“课程明确要求”“论文内容”和“实施建议”分别表述。核查日期：2026-10-22。

## 1. 到底要复现论文，还是要做改进？

结论：课程明确要求完成基线并进行改进/优化，针对“大模型后训练”还明确要求微调、强化学习、自设计奖励、三阶段对比和交互 Demo。参考论文可以提供实现路线，但材料没有指定必须选哪篇作为基线，也没有要求超过参考论文的原始分数。

课程总要求《大作业.pptx》的“要求”部分原文：

> 围绕所选任务完成基线系统，并进行方法改进或优化；在统一评价指标下对比改进前后的实验结果，提交技术报告、Demo及代码仓库。

《大模型后训练.pdf》第 1 页“二、任务要求”原文：

> 自行选择能够处理视频输入的本地开源模型，使用原始模型直接完成视频情感识别，作为基线结果；在统一数据上进行模型微调和强化学习后训练，自行设计奖励函数……

同一段还要求：比较原始模型、微调模型和 RL 后训练模型的情感识别 Macro-F1、模态冲突识别准确率和过度判断率；分析典型案例；Demo 在同一视频上对比原始与后训练模型，需要时追问并根据用户回答更新结果。

据此区分几种做法：

| 做法 | 对照已读取的课程要求 |
| --- | --- |
| 下载 Emotion-LLaMA/R1-Omni 权重，只运行几个例子 | 可以了解能力或作为额外比较，尚未完成本任务微调、RL 和三阶段评价 |
| 完整复现论文原数据、原训练流程和原论文表格 | 有学习价值，但仍需完成课程统一数据上的任务与指定 Demo |
| 借鉴论文训练流程，适配课程数据，再加入冲突、不确定性和追问训练/评价 | 与本题要求直接对应；不必先复现论文全部原实验 |
| 使用自行选择的开源视频/音视频模型，做课程 SFT 和 RL | 材料允许；需要说明参考来源、实际优化、奖励设计与统一对比 |
| 提出全新架构并超过论文所有结果 | 已读取材料没有这一要求，也没有给出必须达到的分数阈值 |

“参考文献”和“示例代码仓库”不是指定基线清单。把论文中的方法适配到课程任务，可以构成课程层面的方法改进/优化；是否足以获得某档成绩，现有材料没有评分细则，不能代老师保证。效果下降也应如实分析，但不能因此省略要求的训练与对比。

本次补查的总要求 PPT 比此前只读取的专题 PDF 多了明确的“方法改进或优化”表述，应以这两份材料合起来理解。课程 GitHub 链接本次未成功读取，Kaggle 登录后的规则亦未核验；本文不推断其隐藏评分权重、外部数据或补标权限。

## 2. “论文模型作为基线”具体指什么？

本作业最清楚的主对照是同一基座的三个状态：

> 未经本课程数据训练的起点 → 课程数据上的 SFT → 继续 RL 后训练。

起点可以是符合输入要求的官方开源指令模型。已有的 Qwen2.5-Omni / Gemma 零样本测试属于这种基线。若选用发布的 Emotion-LLaMA 或 R1-Omni，它们已接受情感专项训练，应明确这段训练历史，不能把它们描述成从未经过情感训练的模型。

论文模型也可以作为额外的外部参照：在同一课程评价集上重新推理、适配输出并评分。论文原表格中的分数不能直接搬来与课程分数比较，因为输入、标签、数据划分和指标不同。若论文输出 angry/happy/surprise 等细粒度情绪，而课程输出 positive/negative/neutral，必须预先说明输出适配；特别是 surprise 不能无条件映射为正向或负向。

单纯把 A 模型换成 B 模型，不能直接证明 SFT/RL 有效；因此三阶段的主要比较应尽量固定基座、划分、媒体处理、提示词和推理设置。

## 3. Emotion-LLaMA：它做什么，数据长什么样？

**Emotion-LLaMA: Multimodal Emotion Recognition and Reasoning with Instruction Tuning**，NeurIPS 2024；本地 PDF 49 页，包含正文、附录、checklist。[论文](https://arxiv.org/abs/2406.11161)｜[作者代码](https://github.com/ZebangCheng/Emotion-LLaMA)｜[本地全文](parsed/emotion-llama.md)。

### 方法与能力

论文把音频、不同视觉信息和文本接入 LLaMA2-chat-7B。音频采用 HuBERT；视觉分别关注面部细节、表情随时间的变化、全图环境。通过投影层与 LoRA 训练，完成两类任务：识别情绪；根据画面、声音和文本线索解释判断。训练主要是由粗到细的指令微调，没有提供课程要求的 RL 训练阶段。[PDF 第 3–6 页，§3–4.2；第 27–28 页，附录 B]

### 核心训练数据 MERR

MERR 基于 MER2023 的影视视频数据构建，作者公开情感描述 JSON，不随标注再分发原视频；原视频需要向数据提供方申请。[PDF 第 10 页，Ethics]

- 粗粒度标注规模：28,618；用于较初步的多模态对齐和训练。
- 细粒度标注规模：4,487；经过进一步整合、筛选和专家审核，提供更详细的情感描述。
- 两个数字描述粗、细两阶段资源，不能直接相加当作互不重复的视频数；附录说明细粒度数据由前述样本进一步精炼而来。
- 附录列出九类情绪：neutral、happy、angry、worried、surprise、sad、fear、doubt、contempt，分别为中性、高兴、生气、担忧、惊讶、难过、害怕、怀疑、轻蔑。
- 大部分视频时长在 2–4 秒。

一条 MERR 样本不只有“视频＋标签”，还包括：音调描述、字幕、场景描述、表情描述、综合情感解释。PDF 第 3 页图 1 的实际例子是：女性说“Oh my!”，眼睛睁大、嘴张开，声音兴奋，标签为 Surprise，并附综合解释。它适合教模型“观察哪些线索、如何说明判断”。[PDF 第 3 页图 1；第 18–20 页，附录 A]

粗标注由 OpenFace、MiniGPT-v2、Qwen-Audio、LLaMA-3 等工具参与生成，再经过筛选/审核，并非所有描述均为人工从头撰写。[PDF 第 3 页及附录 A.2–A.3]

### 评测数据

- MER2023：影视片段上的情绪分类；论文在 MER2023-SEMI 评测。
- MER2024：论文报告噪声条件分类和开放词汇情绪识别。
- DFEW：影视片段上的动态表情识别，论文比较零样本与微调后的结果。
- EMER：包含多模态情绪线索/解释，用于检查解释与参考标注的重合程度；本论文附录描述的是 100 条规模的资源，不能与后续论文引用的版本/子集数直接混用。

论文的主任务和已列训练标注没有覆盖课程的完整“冲突识别→是否追问→用户回答→更新判断”流程。能生成情感解释，不等于已经验证了合理表达不确定性或澄清对话能力。[PDF §3、§4.1、附录 B.1–B.2]

### 能借鉴什么？

适合借鉴多模态线索整理、情感识别与解释的多任务 SFT、对自动标注的人工检查。若完整迁移其实现，还需处理额外编码器、特征准备、权重和环境；作者仓库训练使用预提取特征，不能把课程 JSONL 原封不动当作其训练输入。作者仓库当前描述与论文版本可能存在更新，本次没有实际部署或训练该模型。

## 4. R1-Omni：与作业训练流程最接近

**R1-Omni: Explainable Omni-Multimodal Emotion Recognition with Reinforcement Learning**，2025 技术报告/预印本；本地为 arXiv v2，9 页。[论文](https://arxiv.org/abs/2503.05379)｜[作者代码](https://github.com/HumanMLLM/R1-Omni)｜[本地全文](parsed/r1-omni.md)。

注意：R1-Omni 基于 **HumanOmni-0.5B**，不是 Qwen2.5-Omni-3B。模型名都有 Omni，不代表同一架构或可以直接共用训练配置。

### 训练过程与数据

| 阶段 | 论文采用的数据 | 一条样本提供什么 | 用来学什么 |
| --- | --- | --- | --- |
| 冷启动 SFT | 232 条 EMER 样本＋348 条人工标注的 HumanOmni 样本，论文写明合计 580 条 | 视频/音频＋解释文字＋最终情绪 | 初步情感分析和指定输出格式 |
| RLVR＋GRPO | MAFW 与 DFEW 训练集中的 15,306 条视频样本 | 视频/音频＋情绪类别；这一步没有逐条推理解释监督 | 生成多个回答，按奖励学习提高情绪判断 |
| 分布内评价 | DFEW、MAFW | 情绪标签 | 识别准确性、各类召回 |
| 分布外评价 | RAVDESS | 演员以不同情绪表达固定句子的视听材料 | 检查换到另一类场景后的泛化 |

来源：PDF 第 2 页 §2.1、第 3 页 §3.1、第 6 页 §4。

冷启动示例要求生成 `<think>...</think>` 和 `<answer>angry</answer>`；前者是模型生成的解释，后者是最终标签。RL 数据不需要给每条视频配完整解释，而是根据最终标签是否正确给奖励。生成了长解释，不意味着其中每条线索都真实；作者在第 8 页 §5.2 也承认解释幻觉。

### 奖励具体是什么？

论文 §3.2 将总奖励定义为“情绪正确性奖励＋格式奖励”。情绪与标签一致得 1，否则得 0；符合指定标签格式得 1，否则得 0。[PDF 第 4–5 页，式 5–6]

这套设计可以启发课程 RL，但它没有给“冲突识别是否正确”“该不该追问”“问题是否有用”“根据用户回答更新是否合理”提供完整奖励方案。这些仍要按课程任务设计与验证，不能照搬两项奖励后就声称任务全部解决。

### 所用数据集分别是什么？

- **DFEW**：官方介绍为 16,372 个电影短片，含七类经典表情的单标签及七维表情分布；有复杂光照、遮挡和姿态变化。七类为高兴、难过、中性、生气、惊讶、厌恶、害怕。总资源规模不等于 R1-Omni 实际选取的训练量。[官方数据集](https://dfew-dataset.github.io/)；七类亦见 Emotion-LLaMA 第 7 页表 2。
- **MAFW**：官方说明有 10,045 个电影、电视剧、短视频片段，提供 11 类单情绪、32 类复合情绪组合、中英双语描述和表情分布等。来源跨多个国家和地区。R1-Omni 说明其训练使用情绪类别监督，不代表它使用了 MAFW 提供的全部描述和所有任务。[官方说明](https://github.com/MAFW-database/MAFW)
- **RAVDESS**：24 位专业演员用不同情绪表达固定英文句子，另有歌曲材料；资源提供音频、音视频和无声视频形式。原资源共 7,356 个文件，包含不同模态版本，不能当成同数量的互不重复视频。语音情绪包括中性、平静、高兴、难过、生气、害怕、厌恶、惊讶。R1-Omni 用它做分布外评价，论文没有给出足够细节来确定实际测试文件清单，不把全资源规模写成其测试样本数。[官方数据记录](https://zenodo.org/records/1188976)

这些标注主要告诉模型“是什么情绪”或“为什么这样判断”，并没有给每个视频都配上“应该问用户什么、用户会怎样回答、回答后应怎样修改”的多轮对话。

### 复现时的现实限制

作者仓库提供 HumanOmni、EMER-SFT、MAFW-DFEW-SFT、R1-Omni 的模型入口，但当前 README 的“完整训练数据”和“更详细复现流程”仍列为待完成。现成权重可用于尝试推理，不等于严格原样复现全部训练已经有齐备材料。本次只核查说明，未下载权重、跑推理或训练。

## 5. MER 2024：竞赛/数据说明，而非一个叫 MER2024 的统一模型

**MER 2024: Semi-Supervised Learning, Noise Robustness, and Open-Vocabulary Multimodal Emotion Recognition**，2024；本地是 arXiv v4，8 页，仍含出版模板占位 DOI。[论文](https://arxiv.org/abs/2404.17113)｜[配套 MERTools](https://github.com/zeroQiaoba/MERTools/tree/master/MER2024)｜[本地全文](parsed/mer2024.md)。

论文介绍三个赛道，提供数据、基线和评价规则；**MERTools 是配套代码工具箱**，不等同于一个能直接追问的大语言模型。

### 数据内容和任务

原始片段来自电影、电视剧，按字幕或语音切分，筛选主要人物，长度为 2–16 秒。标注包含画面、音轨、文字等情感信息。[PDF 第 2–3 页，§2.1]

| 部分 | 数据与监督 | 希望研究什么 |
| --- | --- | --- |
| Train&Val | 表 1 为 5,030 条有标签样本 | 提供分类训练/验证数据 |
| MER-SEMI | 115,595 条大池中，1,169 条有用于评价的标签 | 利用大量无标签数据提高情感分类表现 |
| MER-NOISE | 表 1 为 1,170/115,595；带语音干扰与画面模糊 | 在信息变差时保持识别能力 |
| MER-OV | 同一论文表 1 写 322，正文写 332，存在不一致 | 不固定情绪类别和标签个数，允许输出多个情绪词 |

MER-SEMI / MER-NOISE 的固定类别是 worried、happy、neutral、angry、surprised、sad。MER-OV 可输出类似“难过、失望、无助”的多个情绪词；这是帮助理解的示意，不是从论文复制的一条实际样本。[PDF 第 3 页，§2.3–2.4]

“开放词汇”表示输出标签不局限在预设列表，不代表“信息不足时主动提问”。“噪声鲁棒”表示输入变差时仍尽量识别，也不自动等于会恰当表达不确定性。

分类基线主要是各模态提取特征，再注意力融合，报告准确率、加权 F1；开放词汇任务需要处理同义情绪词并比较标签集合。这些评价不能直接替代课程的三分类 Macro-F1、冲突准确率和过度判断率。[PDF 第 3–6 页，§3]

论文赛事规则禁止参赛者自行人工标注 MER2024 样本，也限制 MER-OV 使用闭源模型；这是该赛事的规则，不能直接套用成课程 Kaggle 的规则。反过来，也不能在没有看课程规则前就默认允许使用外部数据、自动补标或人工补标。[PDF 第 3 页，§2.4]

## 6. 它们与课程数据最重要的差别

| 比较项 | 参考论文主要在做什么 | 本课程需要什么 |
| --- | --- | --- |
| 输出类别 | angry/happy 等细粒度情绪，或开放词汇、多标签 | positive/negative/neutral 的综合情感 |
| 数据监督 | 视频级情绪标签，部分资源有线索和解释 | 课程 JSONL 还区分单模态 M1/M2、综合 M12 和 Aligned/Conflict |
| 主要目标 | 情感识别、解释、噪声鲁棒性或泛化 | 识别之外，还需处理冲突、证据不足与追问 |
| 交互形式 | 论文核心训练与评测主要为单次输入、单次回答 | 追问后接收用户补充信息，再更新判断 |
| 比较方式 | 各自数据和指标上的论文实验 | 统一课程数据上比较原始、SFT、RL |

课程数据规模和格式依据当前 README：训练 3,354、验证 666、测试 734 条；VT 是画面＋给定文字、不输入音轨；VA 是画面＋音频、不额外给文字稿。当前本地工作树未包含原始 Dataset，本次未重新逐条检查或追溯全部来源数据。

M1/M2 标签能辅助分析模态差异，但不能仅凭标签不同就自动断定“应当追问”。冲突也可能能够通过上下文消解；不确定性与冲突需要各自的定义和评价。

## 7. 对当前项目的建议

建议保留已有零样本基线，以同一可处理课程模态的基座完成 SFT→RL 主线。R1-Omni 最值得参考的是训练流程和可验证奖励；Emotion-LLaMA 最值得参考的是指令数据与线索组织；MER 2024 最值得参考的是数据/评价和模态分析。是否使用其具体权重，属于实现选择，不是已知的课程硬规定。

下一步先核实课程对额外标注和外部数据的规定；整理训练/验证视频重复情况；定义不确定性、过度判断和澄清问题质量；在训练部分准备所需监督，并单独保留评价样本。若允许模型生成辅助标注，要明确其来源，检查质量，不把生成答案当成独立的人工真值。

然后完成小规模 SFT 保存/重载，再做 RL。主比较固定基座和评测协议，检查情感识别、冲突召回、过度判断与追问；奖励不能只鼓励“总说不确定”。如需体现设计选择，可比较“正确性＋格式”奖励与加入冲突/适当追问后的奖励；这是建议的实验，不是课程指定方案。

不必为了引用参考文献，先把它们的全部数据集申请、下载、训练一遍。需要做到的是：清楚交代借鉴了什么、改了什么，实际完成课程要求，并在统一条件下检验结果。

## 8. 原文与解析中应保留的差异

- **MER-OV 数量不一致**：MER 2024 第 3 页表 1 写 322，§2.3 写 332，第 2 页也写 332。已核对原 PDF 表格截图，不是 MinerU 独自造成的错误；没有实际发布数据清单，不能擅自确定哪个数正确。
- **R1-Omni 指标名对调**：第 6 页表 1 的顺序是 WAR、UAR，正文 §4.2 及后续部分文字对相同数值的指标名反过来。引用结果时需注明依据表 1，不能把正文和表格拼接。
- **EMER 规模不可混写**：Emotion-LLaMA 附录描述 100 条规模，R1-Omni §3.1 写从 EMER 取 232 条用于冷启动，MER 2024 的开放词汇标注段落还涉及 332 条。这些是不同论文/版本/任务的表述，本次未核到共同发布文件清单，不能断言为同一固定版本。
