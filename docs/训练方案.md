# 训练方案（SFT 与 RL）

2026-10-27 起草。目标是把“原始模型 → SFT → RL”三阶段放在同一基座、同一划分、同一推理设置下比较，指标按课程要求给出情感 Macro-F1、冲突识别准确率和过度判断率。

## 1. 固定条件

| 项 | 取值 |
| --- | --- |
| 基座 | `Qwen2.5-Omni-3B`（Thinker 部分），零样本结果见[基线实验](基线实验.md) |
| 数据 | `train.jsonl` 训练，`val.jsonl` 选型与早停，`test_release.jsonl` 只用于出提交 |
| 输入 | VT 走画面 + 文字，VA 走画面 + 音轨；8 帧、最长边 448，与基线一致 |
| 输出 | 单个 JSON：`pred_emotion` / `is_conflict` / `is_uncertain` / `clarifying_question` |
| 推理 | BF16、贪心解码、192 新 token、种子 42 |
| 硬件 | A100-80G 单卡（开发机与训练任务均可） |

三阶段只允许“训练与否”这一个变量变化。提示词、帧数、解码参数、评测脚本都冻结，改动就重跑全部三阶段。

## 2. SFT 数据构造

从训练集 3354 条出发，按目标输出拼样本。每类样本都要能追溯到原始 `sample_id`，便于复核与去重。

| 样本类型 | 来源 | 目标输出 |
| --- | --- | --- |
| 情感判断 | `views.M12.label` | `pred_emotion` 与标签一致，`is_conflict` 按 `sample_type`，`is_uncertain=no`，`clarifying_question=none` |
| 模态冲突 | `sample_type=Conflict`（411 条） | `is_conflict=yes`；情感仍取 M12，避免把“冲突”等同于“不可判” |
| 证据不足（合成） | 训练集内视频截断、加噪、只给静音画面等 | `is_uncertain=yes` + 一个具体追问 |
| 追问与更新（合成） | 见第 4 节 | 问题 → 用户回答 → 修订后的判断 |

要点：

- **不把 Conflict 直接当不确定**。冲突可以消解，是否追问要单独造监督，否则模型会学成“见冲突就拒答”。
- 合成样本只进训练集，且与评价集按 `split_group_id` 隔离；同一视频的衍生样本归到同一边。
- 追问的参考答案允许多种措辞，训练目标是“问出缺失的那一类信息”，不是背句子。

## 3. RL 奖励

用可验证的部分做规则奖励，主观部分留给人工评测，不把模型自评当奖励来源。

| 维度 | 权重 | 判据 |
| --- | ---: | --- |
| 情感正确 | 0.5 | `pred_emotion` 与 M12 一致得 1，否则 0 |
| 冲突识别 | 0.3 | 真冲突判 `yes`、真一致判 `no` 各算对；只判一半按比例给分 |
| 格式合法 | 0.1 | 能解析出完整 JSON 且字段取值合法 |
| 过度追问惩罚 | 0.1 | 一致样本上给 `yes` 扣分；冲突样本上给 `no` 也扣分 |

追问质量不进入自动奖励：措辞多样、无法用字符串匹配判定。它在人工评测里单独打分，避免奖励作弊（例如一律输出同一句“能再说说吗”）。

## 4. 多轮更新与过度判断率

**多轮更新**：从验证集挑 20–30 条冲突或低置信样本，人工写“问题—回答—修订后判断”，覆盖三种结果：改判、保持原判、仍不确定。用户回答可来自人工编写或模拟，来源在文档里标注，不冒充真实用户。

**过度判断率**（拟议口径，非官方定义）：在人工判为“证据不足”的样本上，模型仍给出无保留结论的比例。

```
过度判断率 = 该类样本中 is_uncertain=no 且给出明确情感的条数 / 该类已裁定样本数
```

分母为零记“不可计算”，不写 0。一致性检查：`is_uncertain=yes` 却给了 `none` 追问，计为格式错误而不是不计入。

## 5. 评测协议

三阶段各跑一次完整验证集（666 条），同一脚本、同一缓存媒体：

1. 情感 Macro-F1：验证集只有正向、负向，报两类宏平均，同时报三分类固定口径便于对照。
2. 冲突识别：准确率之外必须报 Precision / Recall / F1（74 条正例，单看准确率会被 88.9% 的全“无冲突”基线骗过）。
3. 过度判断率：在人工评价子集上算，与 `uncertain_rate` 分列，不互相替代。
4. 追问质量：人工 1–5 分或“可用/空泛/误导”三档，抽样不少于 50 条。

## 6. 算力预算

| 阶段 | 预计 | 说明 |
| --- | --- | --- |
| SFT 冒烟 | 20 分钟 | 200 条子集，1 epoch，看 loss 和显存 |
| SFT 全量 | 1–2 小时 | 3354 条，LoRA，1 epoch 起 |
| RL | 2–4 小时 | 依赖 rollout 长度，先小 batch 试 |
| 评测 | 40–60 分钟 | 666 条 × 3 阶段，单卡 3B |

开发机只做调试与冒烟；正式训练走训练任务，代码来源选 Git 仓库，结果写 `/data/runs`。

## 7. 待确认

- LoRA 的 rank/alpha 与目标模块：先按 r=16、全部线性层，训不动再调。
- 合成“证据不足”样本的具体做法（截断 vs 遮挡 vs 静音），要先看 10 条样例再定。
- 过度判断率的人工评价集规模：课程没有规定，先按 60 条估计。
