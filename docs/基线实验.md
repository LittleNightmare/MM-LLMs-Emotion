# 基线实验

实验日期：2026-10-21（北京时间）。以下结果均来自本地验证集。

## 1. 数据格式

任务输出情感 `negative / positive / neutral`、是否存在模态冲突、是否不确定，以及需要时的澄清问题。

| 协议 | 模型输入 | M1 / M2 |
| --- | --- | --- |
| VT（Video + Text） | 视频画面和给定文字，不输入音轨 | 视觉 / 文字 |
| VA（Video + Audio） | 视频画面和完整音轨，不额外输入文字稿 | 视觉 / 音频 |

文件放在 `Dataset/`，JSONL 每行是一条样本。同一视频可分别对应 VT 和 VA 样本。

| 文件 | 样本数 | 视频路径数 | VT | VA |
| --- | ---: | ---: | ---: | ---: |
| `train.jsonl` | 3354 | 2104 | 1780 | 1574 |
| `val.jsonl` | 666 | 412 | 345 | 321 |
| `test_release.jsonl` | 734 | 458 | 385 | 349 |

训练、验证记录的主要字段如下，示例省略了来源和质量备注等字段：

```json
{
  "sample_id": "ch_sims_v2:VT:video_0001:0001",
  "protocol": "VT",
  "video": "videos/video_0001/0001.mp4",
  "text_content": "我不想嫁给李茶",
  "sample_type": "Aligned",
  "views": {
    "M1": {"modality": "vision", "label": "negative", "is_clear": true},
    "M2": {"modality": "text", "label": "negative", "is_clear": true},
    "M12": {"modality": "vision+text", "label": "negative", "is_clear": true}
  },
  "use_in_main": true
}
```

`video` 相对于 `Dataset/`；`media_paths` 是数据制作机器上的绝对路径，本次不使用。情感真值取 `views.M12.label`，冲突真值由 `sample_type` 映射：`Conflict → yes`、`Aligned → no`。全部训练、验证记录中，`Conflict` 对应 M1 与 M2 标签不同。标签、来源和文件名均不进入文字提示词。

测试集只有 `sample_id`、`video`、`text`，没有标签和 `protocol`。上表测试协议数由 ID 中的 `:VT:` / `:VA:` 及生成视频目录 `silent_video_text` / `video_audio` 推断，不能按是否含音轨判断。当前脚本用于训练、验证格式，不能直接用于测试集。

`sample_submission.csv` 有 734 行，列为 `sample_id,pred_emotion,is_uncertain,clarifying_question`；其中占位值不是测试答案。本次推理额外输出 `is_conflict`，供本地评测。

| 标签 | 训练集 | 验证集 |
| --- | ---: | ---: |
| negative | 1944 | 414 |
| positive | 1403 | 252 |
| neutral | 7 | 0 |
| Conflict | 411 | 74（VT 64、VA 10） |

数据没有独立的不确定性真值或标准追问，不能把冲突标签直接当作不确定性标签。本次使用全部验证样本，不按 `use_in_main` 过滤。训练视频 `videos/video_0049/0012.mp4` 与验证视频 `videos/video_0049/0011.mp4` 字节相同，各对应两条协议记录；本次未训练，也未修改原始划分。

## 3. 实验方式

硬件为单张 RTX 4090，报告显存 49140 MiB。环境为 Python 3.12、PyTorch 2.13.0+cu132、Transformers 5.20.2、Accelerate 1.15.0；其余版本见 [requirements-baseline.txt](../requirements-baseline.txt)。

| 项目 | 设置 |
| --- | --- |
| 视频 | 全片均匀采样 8 帧，最长边不超过 448 像素；以 H.264 CRF 18 缓存为无声视频，保留原时长 |
| 音频 | VA 从原视频提取完整音轨，转为 16kHz 单声道；VT 不读取音轨 |
| 编码 | 各模型使用原生处理器；预处理媒体相同，媒体 token 数可能不同 |
| 推理 | 每次 1 条，BF16，贪心生成，最多 192 token，随机种子 42 |
| 模板 | 相同中文任务提示词，各自原生聊天模板；Qwen3.5 设置 `enable_thinking=False` |
| Attention | Qwen 使用 SDPA；Gemma 文本、视觉使用 SDPA，音频使用 eager |
| 停止条件 | 模型生成配置与 tokenizer 的 EOS ID 合集 |

完整提示词保存在各次实验的 `*-config.json`，要求只输出以下格式：

```json
{"pred_emotion":"negative","is_conflict":"no","is_uncertain":"no","clarifying_question":"none"}
```

情感评分从原始回答中提取第一个含 `pred_emotion` 的合法 JSON 对象；字段缺失、值非法或运行失败均计错，保留在分母中，不修复输出。JSON 合格率单独要求整个回答是 JSON 对象、情感值合法、两个判断字段为字符串 `yes/no`、追问字段为字符串。

Macro-F1 默认取验证集中有真值的 negative、positive 两类；固定三类的 Macro-F1 另存于指标文件，无真值 neutral 的 F1 记为 0。冲突 F1 以 `yes` 为正类。不确定性和追问仅统计行为，未计算准确率或过度判断率。以下均非 Kaggle 分数。

五组测试均无运行错误，也没有回答达到 192 token 上限。显存来自 PyTorch `max_memory_allocated`，不含全部 CUDA 和缓存预留开销，不能作为显卡容量下限或训练显存。运行存在并发与缓存差异，不据此作速度排名。

0.8B 有 155 条回答将 `none` 写成未加引号的值，199 条将冲突字段写为布尔值，两类可重叠。只匹配原文中恰好一个合法情感字段的诊断准确率为 265/345 = 76.81%，该计算忽略其余格式错误，不替代主结果 46.09%。

### 离线组合

固定用 Qwen3.5-2B 的 VT 预测、Omni-3B 的 VA 预测，得到 500/666 = **75.08%** 情感准确率，Macro-F1 **0.8120**，冲突 F1 **0.0392**，JSON 合格率 **100%**。仅按协议选择模型，不逐条按答案选结果；方案是在查看验证结果后提出的，未做独立测试验证。这里复用已有预测，没有新增推理，也未测量组合部署的显存与延迟。

## 5. 复现与记录

安装匹配 CUDA 的 PyTorch 后，在仓库根目录执行 `pip install -r requirements-baseline.txt`。按第 2 节提交号下载检查点到 `models/` 下对应目录，例如：

```bash
hf download Qwen/Qwen3.5-2B --revision 15852e8c16360a2fea060d615a32b45270f8a8fc --local-dir models/qwen35-2b
```

准备各模型检查点和 `Dataset/val.jsonl` 后，以下命令顺序执行：

```bash
python scripts/baseline.py --model gemma-e2b --model-path models/gemma-e2b --output outputs/gemma-e2b-val
python scripts/baseline.py --model qwen-omni-7b --model-path models/qwen-omni-7b --output outputs/qwen7b-val
python scripts/baseline.py --model qwen-omni-3b --model-path models/qwen-omni-3b --output outputs/small-qwen-omni-3b-val
python scripts/baseline.py --model qwen35-08b --protocol VT --model-path models/qwen35-08b --output outputs/small-qwen35-08b-vt
python scripts/baseline.py --model qwen35-2b --protocol VT --model-path models/qwen35-2b --output outputs/small-qwen35-2b-vt
```

每次运行保存 `predictions.jsonl`、`metrics.json`、`config.json`、`model_revision.json` 和实际执行的脚本副本。逐条记录包括原始回答、解析结果、真值、媒体哈希、输入字段、token 数、耗时和显存。原样复查首轮 Gemma、7B 实验时，使用证据包中对应的 `baseline_source.py`。

[实验记录目录](../results/small-baselines-20261021/) 中可直接查看配置、指标和检查结果。[证据包](../results/small-baselines-20261021/experiment-evidence.tar.gz) 保留五组完整预测、组合预测、日志、执行脚本、模型卡和权重哈希；不含视频和模型权重。包内文档是当时的历史快照，本文为整理后的实验说明。
